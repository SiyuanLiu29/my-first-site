# 《今天也没什么特别的》
## 互动聊天网页开发需求文档

---

# 一、项目概述

## 1. 项目名称

《今天也没什么特别的》

## 2. 项目类型

移动端优先的互动聊天网页。

网页整体模拟真实微信聊天体验，通过用户选择回复内容、主动点击“发送”，推动一段完整聊天剧情。

## 3. 核心体验

用户进入网页后，不是在“看聊天记录”，而是在“参与一场聊天”。

网页中的用户角色与“张函瑞”之间不是恋爱关系，也不是梦女向互动。

关系应理解为：

- 长期关注他的人
- 对他的成长比较熟悉
- 可以自然关心、吐槽、夸奖
- 但不会表现出占有欲
- 不会出现情侣式暧昧
- 不会出现“只对你这样”等排他性表达
- 不自称“互联网妈妈”
- 不说教

整体感觉应该是：

> 一个很普通的晚上，两个人聊了一会儿。  
> 没有什么大事，但聊完以后觉得心情还不错。

# 二、作品核心气质

关键词：

- 日常
- 温情
- 松弛
- 克制
- 自然
- 熟人感
- 非恋爱
- 非梦女
- 非说教
- 非励志演讲

剧情中 70% 以上内容应保持普通闲聊。

真正有重量的话只出现少量几句。

不要把作品写成：

- 深夜谈心
- 心理访谈
- 成长采访
- 粉丝告白
- 偶像回应粉丝
- 恋爱模拟器
- 好感度游戏

# 四、视觉方向

## 1. 总体视觉

目标是：

**高度还原微信聊天页的视觉体验。**

但不要求像素级复制微信官方品牌素材。

为了避免直接复制官方资产：

- 可以高度还原布局
- 可以高度还原消息气泡比例
- 可以高度还原顶部栏
- 可以高度还原输入框
- 可以高度还原间距
- 可以高度还原字体大小

但：

- 图标建议自行绘制或使用风格相近的线性图标
- 不直接复制微信官方 logo
- 不使用微信官方资源包

# 六、用户回复交互

这是整个网页最重要的交互。

## 1. 候选回复出现方式

轮到用户回复时：

输入框上方出现 2—3 个候选回复。

例如：

`刚洗完澡`

`发呆`

`准备睡了`

候选回复不要做成游戏式大按钮。

推荐做成：

- 小胶囊
- 类似快捷回复
- 类似输入法候选词
- 浅灰背景
- 圆角
- 视觉存在感弱

目的：

不要让用户产生“答题”的感觉。

---

## 2. 用户选择回复

用户点击某个候选回复。

例如：

`发呆`

点击后：

候选文字进入底部输入框。

此时：

- 不自动发送
- 用户仍需要点击绿色“发送”

---

## 3. 发送按钮

没有选择回复时：

发送按钮不可用。

选择回复后：

发送按钮变成可点击绿色状态。

点击发送：

用户消息出现在右侧绿色气泡中。

随后：

- 候选回复消失
- 输入框清空
- 进入张函瑞回复阶段

---

# 七、消息节奏

不要让所有消息一次性出现。

需要模拟真人聊天节奏。

建议：

## 普通短消息

延迟：

0.6—1.2 秒。

## 连续消息

每条之间：

0.4—1 秒。

## 稍长消息

发送前：

显示“对方正在输入…”

1.5—3 秒。

## 情绪稍认真内容

延迟可稍微更久：

2—4 秒。

例如：

用户说：

“感觉你这个人也比以前稳很多。”

此时可以：

显示：

`对方正在输入…`

约 2 秒。

再发送回复。

---

# 八、“正在输入”设计

可以使用微信顶部联系人名称变化方式。

例如：

正常：

张函瑞

打字时：

对方正在输入…

消息发送后恢复：

张函瑞

不要额外弹出加载框。

---

# 九、聊天滚动

每次出现新消息时：

页面自动平滑滚动到底部。

但必须允许用户自己向上翻聊天记录。

如果用户正在查看历史消息：

可以不要强制抢回底部。

只有用户位于底部附近时才自动滚动。

---

# 十、时间显示

不需要每条消息显示时间。

建议只在：

- 聊天开始
- 时间跨度较大
- 最后结束

显示一次。

例如：

`22:36`

最后：

`23:18`

显示方式：

居中

浅灰色

小字号

7. 一点点认真

注意：

这些标题只用于开发逻辑。

网页中不能显示章节标题。

# 十三、结束方式

不要显示：

- THE END
- 完结
- 恭喜完成
- 结局
- 好感度
- 重新开始弹窗

最后停留在微信聊天界面。

最后一条：

`拜拜`

自然留在屏幕上。

---

# 十四、状态逻辑

推荐使用简单状态机。

例如：

```js
currentNode
selectedChoices
userTired
conversationFinished
```

其中唯一真正影响后续内容的变量：

```js
userTired
```

当第 6 题选择：

`我今天也挺累的`

设置：

```js
userTired = true
```

其他选择：

```js
userTired = false
```

结尾根据该变量判断是否触发：

“你刚刚不是说你今天也很累吗”

这一回收细节非常重要，不能删。

---

# 十五、剧情数据结构建议

不要把聊天剧情全部硬编码进 JSX/HTML。

推荐使用 JSON 或 JS 对象。

例如：

```js
{
  id: "node_01",
  messages: [
    {
      sender: "zhr",
      text: "在干嘛",
      delay: 800
    }
  ],
  choices: [
    {
      id: "01A",
      text: "刚洗完澡",
      next: "node_01A"
    },
    {
      id: "01B",
      text: "发呆",
      next: "node_01B"
    },
    {
      id: "01C",
      text: "准备睡了",
      next: "node_01C"
    }
  ]
}
```

这样后续修改台词非常方便。

# 十七、桌面端表现

电脑打开网页时：

不要让聊天界面直接撑满整个网页。

推荐：

页面中央显示一个手机宽度聊天窗口。

例如：

```css
max-width: 430px;
```

背景可使用：

非常浅的灰色。

不要做明显手机外壳。

重点仍然是聊天页面。

例如：

```css
font-family:
-apple-system,
BlinkMacSystemFont,
"PingFang SC",

Arial,
sans-serif;
```

不要使用艺术字体。

# 十九、微信视觉参考

聊天背景：

浅灰。

张函瑞消息：

白色气泡。

用户消息：

微信绿色气泡。

头像：

V1 可以使用统一占位头像。

如果后续需要真实头像，可以再替换。

气泡圆角：

接近微信。

不要过度圆润。

# 二十、动画要求

所有动画都要轻。

禁止：

- 弹跳
- 粒子
- 渐变炫光
- 卡片翻转
- 游戏式特效

允许：

- 消息轻微淡入
- 新消息从下方轻微出现
- 输入状态
- 平滑滚动

动画时间：

150—250ms。

---

# 二十一、用户操作限制

V1 不允许用户自由输入文字。

只能：

1. 点击候选回复
2. 填入输入框
3. 点击发送

原因：

保证剧情完整性。

---

# 二十二、刷新与存档

第一版推荐：

使用 localStorage 保存进度。

保存：

- 当前节点
- 已发送消息
- 用户选择
- userTired

如果刷新：

恢复聊天。

---

# 二十三、重新开始

不要在聊天页面内放“重新开始”。

可以使用以下方式：

URL：

`?reset=true`

或者：

开发阶段增加隐藏 reset 方法。

例如：

长按顶部联系人名称。

正式版本可以不暴露。

---

# 二十四、无障碍

候选回复必须：

- 可点击
- 可键盘聚焦
- 有清晰 hover
- 有 focus 状态

发送按钮要有：

`aria-label="发送"`

---

# 二十五、响应速度

页面加载后不要一进入就立即弹消息。

建议：

加载完成约 800ms 后：

显示：

`在干嘛`

让它感觉像刚收到消息。

《今天也没什么特别的》

Meta description 可写：

一段普通的聊天。

不要透露剧情。

# 二十九、验收标准

完成后必须达到：

## 视觉

- 第一眼像真实聊天软件
- 不像游戏
- 不像视觉小说
- 不像 AI 聊天界面

## 操作

用户可以：

点击回复

→ 回复进入输入框

→ 点击发送

→ 消息出现

→ 张函瑞回复

整个过程流畅。

## 剧情

所有 10 个选择节点均可正常触发。

所有分支最终正确汇流。

第 6 题：

“我今天也挺累的”

必须在结尾触发：

“你刚刚不是说你今天也很累吗”

## 结束

聊天自然结束。

不出现任何结局 UI。

# 三十二、最终开发目标

这个网页最重要的不是功能数量。

而是：

**让用户感觉自己真的在微信里聊了一会儿。**

聊天结束以后：

没有发生大事。

也没有所谓“剧情高潮”。

只是：

> 今天好像也没干什么。  
> 但是还挺开心的。

这就是整个作品的核心。
